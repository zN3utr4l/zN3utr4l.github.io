The agent pipeline

Every task starts from a written brief. Agents implement in parallel; I plan and review.

  • 2,489agent runs, Sep–Nov 2026
  • 84%of my 2026 commits have an agent as co-author
  • MITthe plugins are open source

How it works

  1. 1

    Plan

    Spec and plan, reviewed before any code.

  2. 2

    Brief

    Scope, files, checks: one page.

  3. 3fix loop

    Execute

    A fresh agent, Codex or Claude, picked by risk.

  4. 4

    Review

    Diff plus evidence: commands, counts, screenshots.

  5. 5

    Ship

    Pull request, green CI, merge.

The rules

  • Agents can't push, merge or rewrite history: a hook blocks it.
  • A quota gate refuses launches above 85% of the plan.
  • One fix loop; a second only for security, data, migrations or releases.

What I wrote

  • For the team: a pipeline, a live dashboard and an MCP server that searches code and docs.
  • Open source: the pipeline, the dashboard and gh-guard, which stops a GitHub command under the wrong account.
  • For me: promo-studio, behind my apps' promo videos, and a knowledge base kept by agents.
