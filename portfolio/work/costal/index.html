Context

I joined Costal on 21 Oct 2020 as an apprentice, right after my diploma, and left in Jan 2026. Costal writes software for industrial automation: machines, PLCs, robots, production lines.

The centre of those years is Costradamus: a predictive-maintenance and machine-data platform for Facco's poultry-farming equipment, built to requirements from IEMA US in Chicago. I built it almost entirely.

What I built

  • Costradamus · data collection

    A C#/.NET 6 microservice reads PLCs and drives and stores the time series in PostgreSQL/TimescaleDB, behind a REST API with token auth. It runs with per-customer profiles for Facco and Ferrero.

  • Costradamus · analysis

    Python with Django and DRF: pandas, scikit-learn, Prophet and TensorFlow, change-point detection with ruptures, tuning with Optuna, jobs on Huey/Redis and RabbitMQ. The signals come from tunnel fans, egg belts, nest expellers, manure scrapers and inverter-driven ventilation: torque, DC-bus voltage, currents, cycles, alarms.

  • Costradamus · app and delivery

    A React + TypeScript desktop app packaged with Electron: monthly anomaly dashboard, scheduled and usage-based maintenance, per-motor and per-signal charts, analytics, notifications, user management. Around it: automated PDF reports (WeasyPrint, Plotly), an admin panel, on-premise deployment on Debian with Docker Compose, and user and admin manuals in LaTeX.

  • Industrial communication

    A C# driver library for OPC UA (client, server and information models, shipped as a NuGet package); EtherNet/IP drivers (libplctag, pycomm3); Modbus drivers; an OPC UA simulator in Node.js + Docker; an EtherNet/IP device scanner and tag-list generator; RabbitMQ test tools. Internal Python libraries on Azure Artifacts: a logger, a model tracker, a scheduled-maintenance Django app.

  • Robotics · Kinema

    HMI and control service for a robot cell: an OPC UA server (model built with the OPC UA ModelCompiler) that exchanges production orders, piece counts, times and machine state between MES and PLC; camera targeting with 2D→3D conversion, best-target selection by score, tracking of picked pieces and up to 20 positions sent to the PLC over EtherNet/IP; Yaskawa robot control through the MotoCom SDK. Then an AGV + robot + camera system that picks tomatoes along the row — docking, goals, retries and synchronisation — shown at the Gulfood fair in Dubai.

  • Food machinery · Roboqbo

    For professional food-processing machines, in 2025: a new machine HMI on Raspberry Pi (Quasar client, Node.js server, SQLite, PLC over Modbus and OPC UA), a cloud portal (ASP.NET, PostgreSQL, REST API for the HMI, Expo push notifications, DocFX docs) and a customer chatbot (.NET API, OpenAI module, Salesforce integration, Vite + TypeScript web, Docker Compose on DigitalOcean).

  • Line HMI · ABB

    A production-line HMI with Keyence smart-camera vision, shift register, labeller and a big-screen view, on PostgreSQL, in 2025.

Decisions and trade-offs

  1. Costradamus runs on-premise: Debian and Docker Compose at the customer's plant, with manuals for the users and for the admins.

  2. The collector was load-tested: 3 groups × 7,500 variables, 500 of them changing every second — about 550 MB an hour, 14.4 GB a day of time series.

  3. One data-collection service, with per-customer profiles for Facco and Ferrero.

  4. Shared code ships as packages: the OPC UA driver on NuGet, the Python libraries on Azure Artifacts. I also wrote the company wiki pages on EtherNet/IP and on the OPC UA library (Mar 2021), on Linux CMS setup (Sep 2021) and on Python package publishing (Nov 2022).

  5. The robot cell speaks each side's protocol: OPC UA to the MES, EtherNet/IP to the PLC, the MotoCom SDK to the Yaskawa robot.
